# Codex 多聊天额度恢复

使用本目录的 `location.txt`（全局安装时）定位源码；项目内直接在仓库运行 `./resume`。用户可以在“Codex任务管家”中选择聊天、确认草稿、管理可选任务和收件箱。不要把列出聊天或发现草稿视为加入队列的授权。

- `./resume queue status` 查看队列项目和暂停状态；该状态不证明后台调度器正在运行。需要进程状态时使用应用界面或 `./resume desktop snapshot`，注意后者包含本机草稿和任务原文，不要原样贴出。
- 用户明确指定聊天后，`./resume queue add UUID` 只加入可托管的运行中或额度中断任务，累计续跑默认最多 3 次。草稿和可选任务以应用中的明确选择为准。
- 用户要求暂停时 `./resume queue pause`；只阻止新派发，不终止正在执行的回合。重启或继续仅在用户有明确指示时进行；桌面应用“开始后台调度”会启动独立后台进程，关闭窗口不等于暂停。
- 滑块表示希望最终保留 10/20/30/40%；普通任务派发须两窗口剩余均严格高于保留线 +10 个百分点。可选任务首次启动须两窗口均至少达到保留线 +15，且已加入的正常任务和待处理草稿处理完毕。收尾 10% 是估计，非保证。
- 想法收件箱使用共享执行槽和许可；数据目录中的原话不搬迁，未勾选自动整理的想法不会自动发送。不要同时使用不支持共享许可的旧版执行器。
- 草稿来自 Codex 桌面端内部持久缓存，可能延迟或随版本变化；不可读取时明确报告未知。包含不支持内容的草稿不能自动转发。发送结果不确定时先核对原聊天或收件箱，不自动重发；不要为解决阻塞删除防重记录。
- 账户变化、审批/输入请求、人工停止、未知状态或版本不匹配时停止派发。仅等待自然额度重置，不使用重置券、积分、付费渠道或其他账号。保留原聊天模型、权限与工作目录。

区分模拟验证、真实消息完成、自然五小时重置和自然周重置；截至当前版本后两项仍未完成实测。
