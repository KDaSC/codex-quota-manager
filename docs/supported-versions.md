# 支持的 Codex App 版本

本工具依赖 Codex 桌面 App 的本机 IPC 协议，而不是公开 API。协议会随 App 版本变化，因此采用**精确版本白名单**：不在名单内的版本只允许只读诊断，不会自动续跑。

## 平台功能差异

| 功能 | macOS | Windows |
| --- | --- | --- |
| 单任务续跑（`doctor` / `list` / `check` / `start`） | 支持 | 支持 |
| 本机 Web 控制台 | 支持 | 支持 |
| 多聊天共享队列 | 支持 | 不支持，命令会明确拒绝 |
| 原生任务管家与自动发现 | 支持 | 不支持 |
| 想法收件箱整合 | 支持 | 不支持 |

Windows 用户走单任务模式；队列相关测试在非 macOS 平台会整体跳过，因此 CI 上 Windows 与 Linux 的测试数量少于 macOS。

## 版本不匹配时会发生什么

- `doctor`、`list`、`check` 等只读命令仍可使用，用于判断本机版本与连接状态。
- 只读诊断通过**不等于**允许发送。托管、自动续跑和任何消息写入都会被拒绝，队列停在版本校验这一步。
- App/CLI 在连接期间发生变化时，本次续跑取消，不会带着旧协议继续发送。

## 如何处理 Codex 升级

升级后先跑：

```bash
./resume doctor
```

如果提示版本不支持，有两种选择：

1. 等本仓库适配该版本；
2. 自己适配并提 PR（见下方步骤）。

不要把 `SUPPORTED_*` 改成通配或模糊匹配来“先跑起来”。协议不匹配时的写入风险由用户的真实对话承担。

## 新增一个受支持版本

1. 读官方安装包或本机 App bundle，确认 `CFBundleShortVersionString`、`CFBundleVersion`，Windows 另需确认 CLI 版本。
2. 在 `codex_resume/app.py` 加入精确版本；如需要固定 CLI，同时更新 `MAC_CLI_PAIRS`。若该构建要求官方队列路径，加入 `mac_uses_queue`。
3. 先做只读验证：`doctor` 要能连通并读到真实额度；`list` 与 `check` 要能返回该版本的会话快照。
4. 运行完整回归：`python3 -m unittest discover -s tests -v`，前端改动另跑 `node --test tests/test_ui.cjs` 与 `node --check codex_resume/static/app.js`。
5. 真实发送验证只能在**明确授权、隔离、无副作用**的测试聊天上做；一旦结果不确定就停止，不重发。
6. 在 `CHANGELOG.md` 写明新增的版本组合，以及“只读通过 / 真实发送通过 / 自然额度重置通过”分别到了哪一步。

## 已知验证边界

- macOS：一次五小时自然恢复后无人干预续跑，另一次在人工修复后台后续跑。新增的 22943 组合已验证隔离聊天的真实发送和回读，尚未在该组合上完成自然重置验收。
- Windows：已用免费账号完成一次真实“额度耗尽 → 自然恢复 → 原任务续跑”整周期；本次未重复 Plus 套餐窗口时长，控制器只读取账号返回的真实重置信息。
- 未逐项验证：自然周窗口耗尽后恢复、整机物理重启、长期断网、真实睡眠唤醒。
- macOS 原生任务管家为本机 ad-hoc 签名，未经过 Apple 公证；其他机器首次打开可能被 Gatekeeper 拦截。
