# Codex 任务管家：使用说明

原生任务管家是可选组件：源码在 `inbox/`，需要 macOS 15+。GitHub Release 提供 Apple Silicon（arm64）应用压缩包；Intel Mac 可使用 Swift 工具链自行构建。应用仅为 ad-hoc 签名，未经过 Apple 公证；下载后可能被 macOS 阻止打开，不要关闭系统安全保护。

当前适配的 Codex 版本见 [支持版本矩阵](supported-versions.md)。更新 Codex 后如版本不匹配，派发会停止，需要重新适配验证。

## 下载后首次打开（终端方法）

1. 从 [GitHub Release](https://github.com/KDaSC/codex-quota-manager/releases/latest) 下载应用 ZIP，解压到“下载”文件夹。确认文件来自本项目、版本与电脑架构相符。
2. 安装到“应用程序”之前，打开“终端”，运行下面的命令。此示例适用于解压后的 **0.4.4** 版本；其他版本请将路径改成实际的 `.app` 路径，或输入命令及其后空格，再把解压出的应用拖进终端，按回车。

   ```sh
   xattr -dr com.apple.quarantine ~/Downloads/Codex任务管家-0.4.4.app
   ```

3. 将该 `.app` 拖入“应用程序”，然后打开。此命令只移除指定应用及其内容的下载隔离标记，不会关闭整个系统的安全保护；它不提供苹果签名或公证。只对确认可信的文件使用。如果提示文件不存在，请核对解压位置和文件名；如果仍提示文件损坏、签名错误或无法打开，请先检查原因，不要反复执行命令。

也可以使用苹果的[“仍要打开”方式](https://support.apple.com/zh-cn/102445)处理未公证应用。

在源码根目录构建本机应用：

```sh
python3 inbox/scripts/build_app.py
open ~/Library/Caches/CodexTaskManagerDevelopment
```

构建结束后，将该目录内带版本号的 `Codex任务管家-<版本>.app` 拖入“应用程序”。下面的后台命令假定应用已命名为 `Codex续航.app`；如果名称不同，请将 `--bundle` 的路径换成实际位置。构建只面向当前 Mac 的架构；这不是 Apple Developer ID 签名或公证的分发包。

需要登录后自动恢复后台时，可用仓库内脚本登记（不会修改暂停状态或开关）：

```sh
python3 scripts/install_background.py --bundle /Applications/Codex续航.app
python3 scripts/install_background.py --uninstall   # 停止并移除该后台服务
```

## 基本使用

1. 打开“项目与聊天”，查看五小时和周额度，选择最终希望保留的 10%、20%、30% 或 40%。两窗口均需有可用数据。
2. 输入框缓存有文字时显示“待发送”。选择聊天并核对内容，点击“加入任务”才会入队。附件或格式无法安全转发时，请在 Codex 内处理；未绑定聊天的草稿也不能直接加入。显示依赖 Codex 的内部持久缓存，可能有延迟或因版本变化而不可读取。加入和发送任务不会清空 Codex 原输入框；任务发送后请留意原草稿，避免再手动发送同一内容。
3. 开启“自动续跑全部额度中断的聊天”，即可发现本机未归档聊天中最新回合有明确额度错误的任务。关闭总开关时，按聊天内的单独开关选择。正常完成、人工暂停、审批和输入等待均不会被接管。需要恢复原聊天连接时，程序会核验后加载原聊天。
4. 在“可选任务”中选择目标聊天、填写内容并保存；再点“选择加入队列”才会参与执行。可选任务等待已加入的正常待办和未处理草稿；可选择“暂不处理”草稿以解除这一等待。
5. 开启自动续跑会启动后台；需要继续人工暂停的队列时点击“开始后台调度”。点击“暂停”阻止新派发。需要登录后恢复后台时，请先按上方命令自行登记；人工暂停不会被自动解除。关闭窗口不等于暂停。系统休眠时不会保证准点运行，唤醒后重新读取额度。不要在不同程序中同时启动另一个队列。
6. “想法收件箱”沿用原有本机数据目录（默认 ~/Library/Application Support/IdeaInbox）。未勾选“保存后自动整理”时只保存原话；勾选后才进入共享调度。旧版应用和本应用不能同时打开同一数据目录。

普通任务仅在两个额度窗口的剩余量都严格高于“最终保留 + 10 个百分点”时派发。例如选择 20%，剩余须高于 30%。新增可选任务仅在两个窗口都至少有 35% 时启动。额外 10% 是估计，实际收尾消耗可能不同，不能保证最终一定保留所选额度。

状态未知、等待审批或用户输入、账户变化和人工暂停均不会自动续跑。发送结果不确定时请先到原聊天核对，不能反复添加或重发。程序不使用重置券、不切换账户、不购买额度。

## 验证范围

已验证本机读取项目、聊天、草稿和两个额度窗口；全局及逐聊天开关已实操。2026-10-29 既完成修复后的一次真实恢复，也观察到另一聊天在五小时额度自然恢复后无需人工介入自动续跑并完成。两个聊天各发送一次。隔离服务验证了进程退出后重启且保留暂停；0.4.2正式后台连续三轮扫描成功。精确恢复时序、整机重启和自然周窗口恢复的验证范围详见 ACCEPTANCE.md。

## 源码与开发验证

本工具基于 MIT 许可的 progressrdx/codex-auto-resume，并整合原有 IdeaInbox。当前原生入口支持聊天列表、手动草稿入队和可选任务；早期 CLI 仍可使用，额度规则以当前应用的保留线为准。

在工程根目录运行：

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_ui.cjs
node --check codex_resume/static/app.js
swift build -j 1 --package-path inbox
swift run -j 1 --package-path inbox idea-inbox-check
```

先构建原生 CLI 再运行跨语言测试，跳过不能作为通过。
